# AGENTS.md

## Commands

- `npm run dev` — nodemon on `http://localhost:5050/api` (sibling frontends `../BigBakeBatter` and `../BigBakeBatter-admin` expect it on port 5050)
- `npm run migrate` — **safe** additive upgrade (defaults, index builds). Run after every deploy
- `npm run seed` — **wipes every collection** and loads demo data; refuses hosted (`mongodb+srv://`) or production DBs without `--force`. Never run against the live database
- No test suite. Boot check: `GET /api/health` (200 = DB up, 503 = DB down)
- Missing env vars stop startup (`server.js:checkEnv`); a weak JWT_SECRET refuses to start in production

## Env (.env)

- Required: `MONGO_URI`, `JWT_SECRET`, `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`
- `CORS_ORIGINS` — comma-separated storefront + admin origins; **empty in production blocks every browser** (dev empty = open CORS)
- `RAZORPAY_WEBHOOK_SECRET` — required in production; webhook endpoint is `/api/payments/webhook`

## Structure

- Routes (`src/routes/`) → controllers (`src/controllers/`) → models (`src/models/`). Zod request validation via `validateBody(schema)` (`middleware/validate.js` + `src/validators/`); errors go through `ApiError`/`ApiResponse`, handlers wrapped by `asyncHandler`
- Repetitive admin CRUD (categories, flavours, occasions, add-ons, …) is generated by `utils/crudFactory.js`
- Auth: `middleware/auth.js` — `protect` (JWT, rejects blocked users and tokens older than `passwordChangedAt`), `optionalAuth`, `restrictTo(...roles)`

## Payments & pricing

- The client only ever sends item ids/weights/qtys — prices are computed server-side in `utils/pricing.js` (`priceCart`/`priceForWeight`). `WEIGHTS_DEF` there must stay in sync with its duplicate in `BigBakeBatter/src/data/products.js`
- `POST /orders` verifies the Razorpay signature, checks the Razorpay order amount equals the server-computed total, and is idempotent per payment id
- Refunds marked in admin are records only — actual refunds are issued in the Razorpay dashboard (`refund.processed` webhook auto-marks them)

## Gotchas

- The Razorpay webhook route is mounted **before** `express.json()` with `express.raw({ type: 'application/json' })` (`src/app.js`) — Razorpay signs raw bytes; moving it breaks signature verification
- Rate limits: 300 req/min on `/api`, tighter buckets on login/register and anonymous write endpoints (orders, enquiries, newsletter, track) — keep this in mind when load-testing
- Uploads are written to `./uploads/` on local disk (multer, 5 MB, images only, filename from timestamp+random — never the client's name). On hosts with ephemeral filesystems uploads are lost on redeploy — attach a volume or move to S3/Cloudinary
- **`src/content/sections.js` is the registry of admin-editable site content** (`GET /api/content/schema` exposes it). After editing defaults, regenerate the storefront fallback with `node scripts/sync-site-defaults.mjs ../BigBakeBatter/src/data/siteDefaults.js` — the script also validates the registry (dup keys, undeclared defaults)
- `app.js` sets `trust proxy` — rate limiting relies on it behind hosts like Render/Nginx
